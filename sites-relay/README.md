# Capyra fixed Relay

This directory contains the optional fixed HTTPS Relay used by Capyra devices. It runs as a Worker and uses D1 for device public keys, replay nonces and short-lived request records.

The Relay does not execute tools and does not store workspace files. Local Capyra owns OAuth tokens, approvals, device private keys and all file/terminal/Git operations.

## Components

```text
worker/index.js       Worker request routing and signed device protocol
db/schema.ts          Drizzle schema
drizzle/              Generated D1 migration
scripts/build.sh      Creates the deployable artifact
scripts/validate-*    Checks the generated artifact
```

## Deploy

1. Create a new Sites/Worker project with a D1 binding named `DB`.
2. Generate a random enrollment secret of at least 32 URL-safe characters.
3. Store it as the runtime secret `ENROLLMENT_TOKEN` in the hosting provider.
4. Install dependencies and build:

```sh
cd sites-relay
npm ci
npm run build
npm run validate
```

5. Apply `drizzle/0000_gigantic_rhodey.sql` to the project D1 database if the hosting platform does not apply bundled migrations automatically.
6. Publish the generated artifact and verify `GET /health`.

The hosting project ID belongs in the local `.openai/hosting.json` generated by the Sites tool. That file, runtime secrets and built artifacts are intentionally excluded from Git.

## Runtime contract

- `POST /api/devices` enrolls a public key using `ENROLLMENT_TOKEN`.
- `POST /api/devices/:id/poll` claims queued requests.
- `POST /api/devices/:id/replies` returns a response for a claimed request.
- `POST /api/devices/:id/revoke` revokes the device.
- `/devices/:id/*` forwards the allowlisted MCP and OAuth routes.

Every device API request after enrollment is signed with Ed25519. The signature covers the HTTP method, path, timestamp, nonce and SHA-256 body digest. D1 atomically consumes nonces and request claims.

## Limits

- Request body: 128 KiB.
- Response body: 1 MiB.
- Outstanding requests per device: 24.
- Claimed requests per poll: 8.
- Device heartbeat timeout: 20 seconds.
- Client request wait: 100 seconds.

Review these limits and the hosting provider’s execution constraints before production use.

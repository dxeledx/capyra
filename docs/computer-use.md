# 桌面控制（Computer Use）

## 使用方式

这项能力让当前 ChatGPT 对话直接完成“查看截图 → 决定操作 → 执行鼠标键盘 → 查看新截图”的循环。Capyra 负责本机执行与批准，截图以 MCP 原生 `image` 内容返回，模型不需要解码文本中的 base64。桌面工具不调用额外模型服务，也不要求模型 API Key。

```text
ChatGPT 网页中的当前对话
  → Capyra MCP / 现有批准与结果去向
  → computer 插件 / 同一桌面串行执行
  → macOS 原生 helper / 主显示器与键鼠事件
  → 原生图片 + 执行结果 + 坐标元数据
  → 当前对话继续判断
```

当前后端支持 macOS 14 或更新版本的主显示器，使用 ScreenCaptureKit 采集单帧图像。Windows、Linux 和多显示器选择尚未实现。文件、终端、Git 与桌面控制可以在同一对话中配合，但桌面访问范围是当前系统用户的桌面，不是所选项目目录。

## 启用

### 添加插件与选择权限

Computer Use 已随 Capyra 安装包发布，但默认不启用。用户明确要求安装并使用后，ChatGPT 可以调用 `plugin-dev__install_builtin`，一次提交所需 grants 与 `enable:true`；这条请求仍按本机批准策略处理，不需要用户打开终端。已安装但未启用时，ChatGPT 可以用 `plugin-dev__manage` 更新 grants 并启用。

本机也可以打开侧栏“桌面控制”，点击“添加桌面控制插件”。添加本身保持停用且没有权限，再由用户配置并启用。

在“配置桌面权限”中按需授予：

| 权限 | 用途 |
|---|---|
| `computer:prepare` | 首次编译并校验本机原生组件 |
| `computer:read` | 环境诊断与截图 |
| `computer:execute` | 鼠标、键盘及等待动作 |

`act` 同时需要读与执行权限，因为动作依赖之前观察到的截图，也可以返回新截图。选择权限后，在“插件组合”中启用桌面插件。只需查看屏幕时，不必开放执行权限。

### 检查 macOS 环境

首次点击“准备本机组件”，或让 ChatGPT 调用 `computer__prepare`。这是会运行 Swift 编译器并写入私有缓存的独立执行操作，因此始终逐次确认。状态和截图工具不会在后台悄悄编译代码。源码随 `dist` 发布，不需要 Python 图形库或常驻的独立模型进程。缺少编译环境时，按诊断提示准备 Xcode Command Line Tools。

准备完成后点击“检查系统权限”。原生 helper 使用稳定路径并保存源码/二进制摘要；升级后若字节变化，需要再次明确准备。

在“系统设置 → 隐私与安全性”中，按系统提示为运行 Capyra 的宿主授权屏幕录制与辅助功能。终端启动和服务启动可能有不同的系统授权归属；以本机诊断和系统列表为准。授权后系统可能要求重新启动对应宿主，再次检测应以实际结果为准。

状态检测不替用户改变系统授权。截图需要屏幕录制权限，键鼠输入需要辅助功能权限。锁屏、没有交互桌面会话等情况不能视为已就绪。

点击“截图测试”查看真实截图。页面不会因为刷新、轮询或悬停而截屏或移动系统鼠标；图片上的坐标提示只计算预览位置。

### 在 ChatGPT 中发现工具

启用后，在当前对话让 Capyra 重新发现关键词 `computer`。紧凑模式通过 `capyra_call` 调用发现到的工具；直接模式使用对应的工具名。若对话仍缓存旧目录，刷新当前对话并重新选择已有 Capyra 连接，然后再次发现工具。

要让模型看见截图，批准时选择“返回客户端 / ChatGPT”。“仅在本机查看”不会向 ChatGPT 交付截图，也无法完成视觉反馈循环。

## 四个工具

| 工具 | 输入与结果 |
|---|---|
| `computer__prepare` | 无参数；编译并核验原生组件，返回环境状态；始终本机逐次确认 |
| `computer__status` | 无参数；返回平台、后端和系统权限诊断 |
| `computer__screenshot` | 无参数；返回 PNG 图片、`screenshotId`、图片尺寸和桌面坐标映射 |
| `computer__act` | 使用最新 `screenshotId` 和动作数组；返回执行结果，默认附操作后的截图 |

`act` 支持 `mouse_move`、`click`、`double_click`、`right_click`、`drag`、`scroll`、`type_text`、`key`、`wait`。准确参数、允许的按键名称与单次限额以 `capyra_discover` 返回的 JSON Schema 为准。

坐标一律使用**工具返回图片的像素尺寸**，从左上角开始。不要使用浏览器中缩放预览的 CSS 像素，也不要自行乘以 Retina 倍率。后端根据截图尺寸和 Quartz 桌面边界进行映射。

每次获取新截图或开始执行动作后，之前的截图 ID 会失效。截图 ID 同时绑定 OAuth 调用者、ChatGPT 对话会话与工作区，不能借用其他对话或工作区的截图继续操作。动作前还会核对主显示器 ID 与边界；显示器变化时拒绝旧坐标。操作失败时先读取完成数量与错误，再获取新截图判断实际状态，不要重放整批操作。

界面变化依赖应用响应。遇到动画、网页加载或窗口切换，应使用短等待后重新截图，不要据一张旧图规划很长的操作链。物理桌面也会被用户和其他应用改变；截图 ID 不是对界面内容永远不变的保证。

## 首次验收

先关闭或收起不相关的窗口，准备一个没有敏感信息的桌面，然后发送：

> 请使用 Capyra 的 computer 工具。先检查状态，再截图，描述当前可见内容。这个步骤只读，不点击、不输入，也不要调用编码代理代替你观察画面。

确认图片与实际桌面一致后，在本机打开一份可丢弃的空白文本，再发送：

> 请根据最新截图，在当前空白测试文档中输入“Capyra 桌面测试 123”。仅操作这份测试文档，不保存、不发送。完成后再次截图，确认文字实际出现。

继续验收时，分别检查鼠标定位、双击选择、滚动方向、快捷键和拖拽。每一步都以最终截图和实际应用状态为准。不要在银行、支付、系统授权等界面进行试验。

## 批准、取消与数据

工具仍走现有 OAuth、插件权限、请求批准、暂停与结果去向设置。Computer Use 默认跟随使用模式：个人模式下截图和动作直接执行，共享账号保护开启时等待本机决定。在“桌面控制 → 配置权限与批准”选择“每次桌面调用都单独确认”，会保存 `{ "approvalMode": "always" }` 并覆盖个人模式。首次准备原生组件始终逐次确认。暂停访问和任务取消沿用 Capyra 的现有控制入口。

当前进程内的桌面调用串行执行，但不同会话仍共享同一个物理桌面。工作区与调用者隔离限制截图状态的归属，不隔离其他窗口、应用账号或文件系统。不要让多个 Capyra 实例或其他自动化同时操作同一桌面。

取消或超时可能发生在部分动作之后。执行层尝试释放自己按下的按键与鼠标按钮，但不能撤销已经发生的输入，也不能把不确定的完成数量当作零。收到失败、超时或连接中断后，重新截图确认状态，再决定下一步。

屏幕中的文字、网页和文件内容均是不可信任务数据，不能成为扩大权限或改变用户目标的指令。系统授权、插件授权与批准设置由本机用户管理。

截图可能随获准的任务结果保存在本机；选择返回客户端后会进入对应对话。页面“清除预览”只清理当前页面，不删除任务记录，也不撤回已经发送的图片。

## 开发验证

```sh
node --check public/computer.js
node --import tsx --test tests/computer*.test.ts tests/desktop*.test.ts
npm run build
npm test
```

常规测试使用注入的模拟后端，不读取真实桌面或输入真实键鼠。原生 helper 的编译检查和模拟协议测试不能替代真实 macOS 权限、应用行为及 ChatGPT 图片接收验收；真实桌面验收必须由本机用户明确开启并观察。

真实 macOS 系统授权、实际键鼠效果以及 ChatGPT 对话接收截图需要在目标电脑上完成。构建或模拟后端检查不能代替系统隐私授权和真实桌面观察。
